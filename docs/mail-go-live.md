# เปิดใช้งานการส่งอีเมล QC

ระบบเขียนเสร็จแล้วและ**ปิดอยู่** ไม่มีเมลออกไปได้จนกว่าจะทำตามเอกสารนี้

ตอนนี้กดปุ่มอะไรก็ได้โดยไม่ต้องกลัว — API จะรันทุกขั้นตอนจริงแล้วรายงานว่า
*"ถ้าเปิดจะส่งถึงใครบ้าง"* แต่ไม่ส่ง

---

## ทำไมถึงเป็นตัวแปรใน Vercel ไม่ใช่ปุ่มในเว็บ

การเปิดเมลจริงถึงคน 34 คน ซึ่งมีผู้บริหารอยู่ด้วย ควรต้องตั้งใจเข้าไปกดใน
console ไม่ใช่พลาดคลิกโดนในหน้า Admin — และถ้าต้องหยุดกะทันหัน การลบตัวแปรทิ้ง
หยุดได้ทั้งระบบทันทีโดยไม่ต้องแก้โค้ด

---

## ก่อนเปิด — เช็ค 3 อย่าง

**1. เติมอีเมลคนที่ยังขาด**

Admin → 📧 ผู้รับเมล QC → แถบเตือนสีแดงด้านบนจะบอกว่าใครยังไม่มีอีเมล
กดที่ชื่อเพื่อเพิ่มได้เลย ตอนเขียนเอกสารนี้เหลือ 11 คน — คนที่ค้างไว้จะไม่ได้รับเมล
แบบเงียบ ๆ

**2. เช็คคนที่สวิตช์ปิดอยู่**

ในตารางเดียวกัน คนที่ `เปิดใช้` ไม่ติ๊กจะไม่ได้รับอะไรเลย ตอนย้ายข้อมูลมาจาก
ชีทเดิมมี 16 จาก 34 คนที่ปิดอยู่ ต้องดูว่าตั้งใจปิดจริงไหม

**3. ทดลองกับใบจริง**

กดปุ่ม **🔍 ทดลองดูว่าจะส่งถึงใคร** ในหน้าเดียวกัน จะได้รายชื่อผู้รับที่คำนวณจาก
ใบล่าสุดจริง พร้อมเหตุผลรายคน — ตรวจว่าถูกก่อนเปิด

---

## เปิด — 2 ขั้น ไม่ใช่ขั้นเดียว

มีสวิตช์ 2 ตัวเรียงกัน เพื่อไม่ให้ตั้งพลาดครั้งเดียวแล้วเมลกระจายถึง 34 คนทันที

| Key | ค่า | ผล |
|---|---|---|
| `QC_MAIL_ENABLED` | `true` | เปิดให้ส่งเมลได้ |
| `QC_MAIL_ONLY_TO` | ไม่ต้องตั้ง | **ค่าเริ่มต้น = ส่งเข้า `sls03@cometsintertrade.com` เท่านั้น** |

### ขั้นที่ 1 — ทดสอบด้วยกล่องเดียว

ตั้งแค่ `QC_MAIL_ENABLED=true` แล้ว redeploy

เมลจะออกจริงแต่**เข้าแค่ `sls03@` กล่องเดียว** ไม่ถึงใครอีกเลย ในตัวเมลจะมีแถบเหลืองด้านบน
บอกว่า *"ถ้าเปิดใช้งานจริง จะส่งถึง N คน"* พร้อมรายชื่อและเหตุผลรายคน — ใช้ตรวจว่ากติกาถูก
ก่อนปล่อยของจริง

หัวข้อเมลจะมีคำว่า `[ทดสอบ]` นำหน้า

**สำคัญ:** เมลในโหมดนี้**ไม่บันทึก snapshot** และไม่เก็บ `Message-ID` เพราะยังไม่ได้ถึงผู้รับจริง
ถ้าบันทึกไว้ พอเปิดของจริงระบบจะคิดว่า "ส่งแล้ว ไม่มีอะไรเปลี่ยน" แล้วข้ามไป — ใบนั้นจะไม่มีใครได้รับ
เลยตลอดกาล · ในประวัติจะขึ้นเป็น `TEST`

### ขั้นที่ 2 — ปล่อยของจริง

เมื่อตรวจแล้วพอใจ เพิ่มตัวแปร

| Key | ค่า |
|---|---|
| `QC_MAIL_ONLY_TO` | `off` |

แล้ว redeploy — เมลจะเริ่มส่งถึงผู้รับจริงตามกติกา

> อยากส่งเข้าหลายกล่องตอนทดสอบก็ได้ ใส่คั่นด้วย comma
> `QC_MAIL_ONLY_TO=sls03@cometsintertrade.com,11181@cometsintertrade.com`

ต้องมี SMTP ตั้งไว้อยู่แล้วด้วย — `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS`
`SMTP_FROM_NAME` ซึ่งใช้ร่วมกับ `notify-reject.ts` เดิม

**ปิดกลับ:** ลบตัวแปร `QC_MAIL_ENABLED` แล้ว redeploy

## Cron sweep ทุก 5 นาที — ยังไม่ได้เปิด

ระบบเดิมบน Apps Script มี trigger ทุก 5 นาทีคอยกวาดใบที่ข้อมูลเปลี่ยนแล้วส่ง
อัปเดต ฝั่งนี้ทำเหมือนกันได้ด้วย Vercel Cron แต่**ยังไม่ได้ตั้งไว้** ตามที่ตกลงกัน
ว่าจะเปิดหลังอนุญาตให้ส่งเมลแล้วเท่านั้น

### ข้อจำกัดที่ต้องรู้ก่อน

Vercel **Hobby (ฟรี) รันได้วันละครั้ง** เท่านั้น ถ้าอยากได้ทุก 5 นาทีจริง ๆ ต้องเป็น
Pro — ควรตัดสินใจเรื่องนี้ก่อนวางแผน

ข้อดีแถมของการมี cron: มันยิงเข้า Supabase สม่ำเสมอ ทำให้โปรเจกต์ free tier
ไม่หลับเองจากการไม่มีทราฟฟิก ~7 วัน

### วิธีเปิด

1. ตั้งตัวแปร `CRON_SECRET` ใน Vercel เป็นค่าสุ่มยาว ๆ — กันคนนอกยิง endpoint
2. เพิ่มลงใน `web/vercel.json`:

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }],
  "crons": [
    { "path": "/api/notify-qc?sweep=1", "schedule": "*/5 * * * *" }
  ]
}
```

3. Deploy

sweep จะกวาดใบที่ `order_date` ย้อนหลังไม่เกิน 30 วัน สถานะสมบูรณ์แล้ว
สูงสุด 200 ใบต่อรอบ ใบที่ข้อมูลไม่เปลี่ยน (snapshot เดิม) จะถูกข้าม ไม่ส่งซ้ำ

ยิงเองเพื่อทดสอบก็ได้:

```
curl "https://web-mocha-three-44.vercel.app/api/notify-qc?sweep=1&dry=1" \
     -H "Authorization: Bearer <CRON_SECRET>"
```

## กันส่งซ้ำ / กันเมลแตก thread

**snapshot** — ทุกครั้งจะคำนวณ SHA-256 จากฟิลด์ที่สำคัญ (จำนวน สถานะ ผู้รับผิดชอบ
รายการ Defect ฯลฯ) ถ้าค่าเดิมแปลว่าไม่มีอะไรเปลี่ยน จะไม่ส่ง นี่คือสิ่งที่ทำให้
รัน sweep ทุก 5 นาทีได้โดยไม่รบกวนใคร

snapshot จะถูกบันทึก**หลังส่งสำเร็จเท่านั้น** ถ้าส่งพลาด รอบถัดไปจะลองใหม่
ไม่ใช่ถูกมาร์กว่าทำแล้วทั้งที่ยังไม่ได้ส่ง

**threading** — เก็บ `Message-ID` ของเมลฉบับแรกไว้ที่ `qc_orders.mail_message_id`
ฉบับต่อ ๆ ไปอ้างถึงตัวนั้นผ่าน `In-Reply-To` / `References` อัปเดตผลจึงไปต่อท้าย
เมลเดิมในกล่องจดหมาย ไม่กลายเป็นเมลใหม่

ระบบเดิมใช้ `thread.replyAll()` ของ Gmail ซึ่งฝั่งนี้ไม่มี เพราะส่งผ่าน SMTP ธรรมดา
ผลลัพธ์ที่ผู้รับเห็นเหมือนกัน แต่กลไกคนละแบบ

## กติกาส่งถึงใคร

ไม่มีอะไรฝังอยู่ในโค้ด ทุกอย่างมาจากตาราง `mail_recipients` ที่แก้ได้ในหน้า Admin

| สถานะ | ผู้รับผิดชอบในใบที่ได้รับ |
|---|---|
| ต่ำกว่า 3% ทุกสถานะ | SCM |
| Accept ≥3% | SCM · PCM · PUR |
| Accept Lot ≥3% | SCM · PCM · PUR · Sales |
| Reject ≥3% | SCM · PCM · PUR · Sales |
| ของเข้า ICT (ทุก %) | SCM · PCM · PUR · Sales |

บวกกับคนที่ตั้งค่าไว้ว่ารับประจำ — `ทุกฉบับ` หรือรับตามสถานะ

**เมื่อใบไม่มีผู้รับผิดชอบ** เช่น 87 แบรนด์ที่ SCM เป็น `Non Active` จะส่งให้คนที่ตั้ง
`fallback_for` ไว้แทน ตอนนี้คือพี่นัสรีน (SCM Manager) — เปลี่ยนได้ที่ patch-31
หรือแก้ในตารางโดยตรง

**สีแถบในเมล** Reject ≥10% แดงเกือบดำ · ≥5% แดงเข้ม · ≥3% แดงอ่อน ·
Accept Lot เหลือง · Accept กับ ICT เขียว
